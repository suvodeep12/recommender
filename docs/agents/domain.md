# Domain Docs

This is a single-context repository.

## Before exploring code

Read these files when they exist:

- `CONTEXT.md` at the repository root.
- Relevant decisions under `docs/adr/`.

If either location is absent, continue without creating placeholder files. Create domain documentation only when the project has a resolved concept or architectural decision worth recording.

## Vocabulary

Use the terms defined in `CONTEXT.md` for issue titles, proposals, tests, and refactors. If a needed term is missing, treat that as a possible domain-model gap instead of silently inventing competing terminology.

## ADR conflicts

If a proposed change conflicts with an existing ADR, identify the ADR and surface the conflict before changing the design.
